# Val Journal - 2025-12-06

## Streams Playground Debugging Session

### Root Cause: Reactive Binding Broken

**Symptom**: Charts display flat lines. Start button fires, events generate, but visualizations don't update.

**Diagnosis**:

```
handleStart → metricsOps.recordEmission()
                     ↓
         Effect runs in runtime, updates MetricsCollector
                     ↓
         BUT: Reactivity.stream() never fires (handlers stubbed)
                     ↓
         throughputAtom never gets new values
                     ↓
         Chart stays flat
```

**Root Cause**: The atoms use `Reactivity.stream([Keys.throughput], ...)` which depends on event-driven key invalidation via `Reactivity.layerKeyPersist()` and `EventLog.layerHandler()`.

These APIs were stubbed out because they don't exist in the current version of `@effect/experimental`. The stubs are `Layer.empty`, meaning:
- No handlers fire when events occur
- No keys get invalidated
- `Reactivity.stream()` never emits new values
- Atoms stay at initial value forever

**Files Affected**:
- `src/lib/streams/playground/events/handlers.ts` - Stubbed
- `src/lib/streams/playground/events/reactivity.ts` - Stubbed
- `src/lib/streams/playground/atoms/index.ts` - Uses broken Reactivity.stream

**Resolution Path**: Research correct @effect/experimental API and implement proper event-driven invalidation.

### Resolution: Correct @effect/experimental APIs

**Research via DeepWiki** revealed the correct APIs (original assumptions were wrong):

| Wrong API | Correct API |
|-----------|-------------|
| `EventLog.layerHandler()` | `EventLog.group()` with `handlers.handle()` |
| `Reactivity.layerKeyPersist()` | `EventLog.groupReactivity()` |
| `Identity.layerRandom` | `EventLog.layerIdentityKvs({ key: "..." })` |
| `Reactivity.stream(keys, effect)` | `Reactivity.stream(effect, keys)` ← data-last! |

**handlers.ts** - Correct Pattern:
```typescript
export const DataFlowHandlersLive = EventLog.group(
  DataFlowEvents,
  (handlers) =>
    handlers
      .handle("DataEmitted", ({ payload }) =>
        Effect.gen(function* () {
          const collector = yield* MetricsCollector
          yield* collector.recordEmission(payload.latencyMs)
        })
      )
      .handle("StreamCompleted", ...)
      .handle("StreamErrored", ...)
)
```

**reactivity.ts** - Correct Pattern:
```typescript
export const DataFlowReactivityLive = EventLog.groupReactivity(
  DataFlowEvents,
  {
    DataEmitted: [Keys.dataFlow, Keys.throughput, Keys.all],
    StreamCompleted: [Keys.dataFlow, Keys.all],
    StreamErrored: [Keys.dataFlow, Keys.all],
  }
)
```

**atoms/index.ts** - Layer Composition:
```typescript
export const PlaygroundEventLogLive = Layer.mergeAll(
  MetricsCollectorLive,
  PlaygroundHandlersLive,
  PlaygroundReactivityLive
).pipe(
  Layer.provideMerge(EventLog.layerEventLog),
  Layer.provideMerge(EventJournal.layerMemory),
  Layer.provideMerge(EventLog.layerIdentityKvs({ key: "playground" }))
)
```

**atoms/index.ts** - Reactivity.stream (data-last!):
```typescript
export const throughputAtom = playgroundRuntimeAtom.atom(
  Reactivity.stream(
    Effect.gen(function* () {      // effect FIRST
      const collector = yield* MetricsCollector
      return yield* collector.getThroughput()
    }),
    [Keys.throughput]               // keys SECOND
  ).pipe(Stream.runLast, ...)
)
```

**Status**: TypeScript compiles, 39 tests pass. Ready for browser testing.

### Browser Testing: Additional Bugs Found

#### Bug 2: `metricsOps.recordEmission is not a function`

**Category**: Binding

**Symptom**: Console error on Start button click:
```
StreamsPlayground.tsx:367 Uncaught TypeError: metricsOps.recordEmission is not a function
```

**Root Cause**: `runtimeAtom.fn()` returns a `Writable` atom, NOT a callable function. The StreamsPlayground was calling `metricsOps.recordEmission(latency)` directly.

**Fix** (`StreamsPlayground.tsx`):
```typescript
import { useAtomSet } from '@effect-atom/atom-react'

// Inside component:
const recordEmission = useAtomSet(metricsOps.recordEmission)
const resetMetrics = useAtomSet(metricsOps.reset)

// In handlers:
recordEmission(latency)  // ← Now callable!
```

---

#### Bug 3: `Maximum update depth exceeded`

**Category**: Lifecycle (infinite render loop)

**Symptom**: Console error:
```
ThroughputPanel.tsx:59 Maximum update depth exceeded.
```

**Root Cause**: `defaultThroughputMetrics()` used `Date.now()` for timestamp:
1. Atom returns Failure (loading) → default called → new `Date.now()`
2. `useEffect` depends on `throughput.timestamp`
3. New timestamp → triggers effect → `setTimeseries` → re-render
4. Still Failure → new default → new timestamp → infinite loop

**Fix** (`types.ts`):
```typescript
// Before:
timestamp: Date.now(),  // ← New value every render!

// After:
timestamp: 0,  // 0 = sentinel for "no data yet"
```

The `useEffect` already guards: `if (throughput.timestamp > 0)` — sentinel 0 skips update.

#### Bug 4: EventLog Events Not Emitted

**Category**: Binding

**Symptom**: Events appear in EventLogPanel (local state), but charts stay flat.

**Root Cause**: `metricsOps.recordEmission` was calling `collector.recordEmission()` directly, bypassing the EventLog entirely.

```
BROKEN FLOW:
recordEmission(latency) → collector.recordEmission() → updates internal Ref
                                                       ↳ NO EventLog event!
                                                       ↳ Handlers never fire
                                                       ↳ Reactivity never invalidates
                                                       ↳ Atoms never update
```

**Fix** (`atoms/index.ts`):
```typescript
import { EventLog } from "@effect/experimental"
import { KeyValueStore } from "@effect/platform"
import { StreamsPlaygroundEvents } from "../events"

// Layer composition - add KeyValueStore for Identity
export const PlaygroundEventLogLive = Layer.mergeAll(...).pipe(
  Layer.provideMerge(EventLog.layerEventLog),
  Layer.provideMerge(EventJournal.layerMemory),
  Layer.provideMerge(EventLog.layerIdentityKvs({ key: "playground" })),
  Layer.provideMerge(KeyValueStore.layerMemory)  // ← Required!
)

// Emit events via EventLog.makeClient
export const metricsOps = {
  recordEmission: playgroundRuntimeAtom.fn(
    (latencyMs: number) =>
      Effect.gen(function* () {
        const emit = yield* EventLog.makeClient(StreamsPlaygroundEvents)
        emitCount++
        yield* emit("DataEmitted", {
          sourceId: "playground" as SourceId,
          timestamp: Date.now(),
          latencyMs,
          emitCount,
        })
      })
  ),
  // ...
}
```

**Correct Flow**:
```
recordEmission(latency) → emit("DataEmitted", payload)
                              ↓
                         EventLog.write()
                              ↓
                         Handler fires (DataFlowHandlersLive)
                              ↓
                         collector.recordEmission()
                              ↓
                         Reactivity invalidates Keys.throughput
                              ↓
                         Reactivity.stream() re-fires
                              ↓
                         throughputAtom updates
                              ↓
                         Chart renders new data!
```

### Discovery: Registry Scoping Problem

Browser testing revealed events appearing in EventLogPanel but charts still flat.

**Root Cause**: Each `EventLog.group()` creates its own scoped `Registry`. The handlers register in Registry A, but `EventLog.layerEventLog` creates Registry B. When `EventLog.makeClient` writes events, it looks in Registry B — which is empty.

```
SCOPING ISSUE:
EventLog.group(Events, handlers)
     └─ creates Registry.layer (scoped, discarded after group builds)

EventLog.layerEventLog
     └─ creates DIFFERENT Registry.layer

metricsOps.emit("DataEmitted")
     └─ EventLog.write() looks for handlers in EventLog's Registry
     └─ Registry is EMPTY → no handlers fire
     └─ Reactivity never invalidates
     └─ Charts stay flat
```

### Strategic Decision: Decouple Hot Path from EventLog

**Question posed**: Should we flatten scopes (share Registry) or decouple hot path?

**Answer**: **Decouple**. The hot path must remain fast. EventLog is for reactivity, not every emission.

### Research: Effect Stream Primitives

Consulted `submodules/website/content/src/content/docs/docs/stream/` for canonical patterns.

**Key primitives discovered**:

| Primitive | Use Case |
|-----------|----------|
| `Stream.fromQueue` | Async queue → Stream |
| `Stream.fromPubSub` | PubSub messaging → Stream |
| `Stream.partition` | Split stream by predicate |
| `Stream.partitionEither` | Split by effectful predicate |
| `Stream.groupedWithin(n, duration)` | Batch by count OR time |
| `Stream.throttle` | Token bucket rate limiting |
| `Stream.debounce` | Emit only after quiet period |

### Decision Point: Hybrid Partition + Downsample

**Use Case**: CNC vibration analysis machine emitting 10kHz samples. Cannot DoS the EventLog.

**Architecture**:

```
                                    ┌─────────────────────────────┐
                                    │   HOT PATH (always fast)    │
                                    │   collector.record(sample)  │
                                    │   No EventLog, no delay     │
emissions ──► Stream.partition ────►├─────────────────────────────┤
              (shouldSample)        │   SAMPLE PATH (downsampled) │
                                    │   throttle/groupedWithin    │
                                    │   → EventLog.emit()         │
                                    │   → Reactivity invalidates  │
                                    │   → Atoms update            │
                                    │   → Charts render           │
                                    └─────────────────────────────┘
```

**Downsample strategies** (to be determined):

| Strategy | Behavior | Use Case |
|----------|----------|----------|
| `throttle(enforce)` | Drop excess, keep rate | Steady UI updates |
| `throttle(shape)` | Delay to match rate | Preserve all samples (slower) |
| `groupedWithin(100, "1s")` | Batch then emit | Aggregate metrics |
| `debounce("100ms")` | Only emit after pause | Bursty sources |

**Key insight**: Partition is the fork. Downsample is the policy on the sample leg.

### Implementation Plan

1. Create `MetricsStream` service with internal PubSub
2. Hot path publishes to PubSub (fire-and-forget)
3. Two consumers subscribe:
   - **Collector consumer**: `Stream.runForEach(collector.record)` — always, fast
   - **Sample consumer**: `Stream.throttle → EventLog.emit` — rate-limited
4. Atoms subscribe via `Reactivity.stream` as before

**Status**: ✅ Implemented.

### Implementation: MetricsStream Service

**Files Created/Modified**:

| File | Change |
|------|--------|

| `playground/atoms/index.ts` | Replaced EventLog/Reactivity with polling atoms |

**MetricsStream.ts** — Core service:

```typescript
export class MetricsStream extends Context.Tag("tmnl/streams/MetricsStream")<
  MetricsStream,
  MetricsStreamShape
>() {}

interface MetricsStreamShape {
  readonly publish: (latencyMs: number) => Effect.Effect<void>  // Hot path
  readonly reset: () => Effect.Effect<void>
  readonly shutdown: () => Effect.Effect<void>
}
```

**Internal Architecture**:

```typescript
// PubSub with sliding buffer (drops oldest if full)
const pubsub = yield* PubSub.sliding<EmissionSample>(10000)

// Collector consumer: every emission → collector.recordEmission
const collectorConsumer = Stream.fromPubSub(pubsub).pipe(
  Stream.runForEach((sample) => collector.recordEmission(sample.latencyMs))
)

// Sample consumer: 100ms batches → aggregate metrics
const sampleConsumer = Stream.fromPubSub(pubsub).pipe(
  Stream.groupedWithin(1000, "100 millis"),
  Stream.mapEffect((batch) => /* compute aggregates */),
  Stream.runDrain
)
```

**Polling Atoms** (replaced Reactivity.stream):

```typescript
export const throughputAtom = playgroundRuntimeAtom.atom(
  Stream.fromSchedule(Schedule.spaced("100 millis")).pipe(
    Stream.mapEffect(() =>
      Effect.gen(function* () {
        const collector = yield* MetricsCollector
        return yield* collector.getThroughput()
      })
    ),
    Stream.runLast,
    Effect.map((opt) => opt ?? defaultThroughputMetrics())
  )
)
```

**Why polling instead of Reactivity.stream**:

1. Hot path bypasses EventLog → no key invalidation events
2. Polling interval matches sample interval (100ms) → consistent UX
3. No Registry scoping issues → simpler architecture
4. Effect services still provide DI, just without Reactivity layer

**TypeScript**: Compiles clean.

**Component**: `StreamsPlayground.tsx` already uses correct pattern:
```typescript
const recordEmission = useAtomSet(metricsOps.recordEmission)
recordEmission(latency)  // Hot path via MetricsStream.publish
```
