Canonical continuity chain (must be unbroken)

1) Intent

Operator action/hotkey/request (e.g. fly, corridor, alert).

2) Contract

Effect Schema validates input/state shape (no raw drift).

3) Control

MapController applies deterministic mutation or compute path.

4) State

Panel-scoped atoms updated (isolated by panelId).

5) Render

GeointMap/DeckGL consumes atom state and emits visible layer change.

6) Feedback

User sees outcome; tests verify no cross-panel bleed and no race regressions.

Critical fail points (scrutinize first)

  • Split-brain visibility: MapController.layerVisibilityAtom and GeointMap instance visibilityAtom are not a single continuity path.
  • Map style continuity gap: mapStyleAtom mutations are not yet a guaranteed GeointMap style source-of-truth in the render path.
  • Latent method drift risk: Wave 2/3 methods can pass tests while still delivering no visible operator outcome.
  • API shape pressure: method count is high; without status badges + grouping, operator mental model degrades quickly.

Continuity hardening sequence (failure-first)

  • Gate A: unify render source for style + visibility (controller state must drive map output directly).
  • Gate B: wire 3 latent methods to visible DeckGL layers (recommend: air corridor, uncertainty, CAP alerts).
  • Gate C: attach latent badges in operator UI/docs for all non-rendered methods.
  • Gate D: add per-method integration assertions: intent → atom → rendered layer diff.
This is a continuity artifact, not a marketing sheet. If a method cannot be traced through all 6 chain stages, treat it as non-continuous until proven otherwise.
