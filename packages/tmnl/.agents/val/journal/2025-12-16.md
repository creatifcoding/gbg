# 2025-12-16 — The Emacs Constellation Aligns

## Context

Five days since last journal (Dec 11). Massive ground covered: Variables v2, Phase 0 infra deployment, UI system overhauls, brand assets, Settings system scaffolding. The Emacs-inspired architecture vision is crystallizing — commands separated from minibuffer, variables system implemented, hotkeys reorganized with WhichKey.

- **Strategy chosen**: Emacs model as architectural north star
- **Approach**: Vertical slices through EDIN cycles, infrastructure foundation laid

## Changes

### Variables System v2 (`src/lib/variables/v2/`)

| File | Action |
|------|--------|
| `Variable.ts` | Core variable definition + resolution engine |
| `VariableProvider.ts` | Effect-based provider with scoped resolution |
| `config.ts` | Default variable definitions (editor, appearance, behavior) |
| `hooks.ts` | `useVariable()`, `useVariableValue()`, `useVariables()` hooks |
| `internal/core.ts` | Schema-validated storage with Effect.Ref |
| `internal/scope.ts` | Scoped value resolution (global → workspace → editor) |
| `atoms/index.ts` | Atom-based reactive bindings |

Key design: `group` field is now **explicit** on all variables (not inferred from ID prefix). Consumers robust against missing registrations.

### Command System Effect-ification

- `wire.ts` and `useCommandWire.tsx` now use tagged Effect errors
- No more try/catch blocks — proper `Effect.catchTag` patterns
- Error types: `CommandRegistrationError`, `BindingRegistrationError`, `ProviderRegistrationError`

## Lessons

1. **Group field explicit**: Inferring variable groups from ID prefixes was fragile. Explicit `group` field is cleaner.
2. **Infrastructure first**: Phase 0 (NATS + Postgres) unlocks backend development. Can't build services without foundation.
3. **Emacs model validation**: Separating commands from minibuffer (EPOCH-0003) proved the architectural value of following Emacs patterns.
