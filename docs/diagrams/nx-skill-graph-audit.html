NX Skill — Structure Audit

Mapping what you asked for → what exists → what's missing

What You Requested

Requirements
  • Standardized plugin briefings — each plugin follows the same shape
  • Meta-template — "how to write a reference doc" for any entity type
  • DAG dependency language — explicit prereqs between nodes, not just "Back to"
  • Skill graph observability — agent sees the full topology and routes through it
  • Entity-type standardization — generators, plugins, boundaries each have a canonical doc shape
Design Principle

Treat the skill like component decomposition. Each doc node is a "component" with:

  • Props — what it expects (prereqs/deps)
  • Renders — what it provides (knowledge surface)
  • Children — what it links to (deeper nodes)
  • Shape — standardized template per entity type

Progressive disclosure. Agent bounces through indexes. No node over ~80 lines. DAG, not a tree — cross-links are explicit.

Proposed Improvements

1. Frontmatter Protocol

Every doc gets a YAML-style header block:

# Title

> up: ../INDEX.md
> prereqs: boundaries/INDEX.md, effect-v4/INDEX.md
> provides: plugin-writing, createNodesV2-api
> children: createNodesV2.md, local-plugin.md

Agent reads header → knows prereqs to load first, children to drill into, and what knowledge this node provides.

2. TEMPLATE.md — Entity Shapes

Canonical doc shape per entity type:

  • Plugin Brief: Name, Source, Infers From, Targets, Options, When To Care
  • Generator Doc: Name, Usage, Creates, Updates, Options, Example
  • Boundary Rule: Rule, Source Tag, Constraint, Rationale, Violation Message
  • Strategy Doc: Problem, Solution, Why Not X, Migration Path

New agent copies the shape. Consistency emerges from templates, not memory.

3. GRAPH.md — Topology Map

Machine-readable + human-readable graph at skill root:

SKILL.md
├──[routes]─→ references/INDEX.md
│   ├──[contains]─→ plugins/INDEX.md
│   │   ├── createNodesV2.md
│   │   │   prereqs: [boundaries/INDEX]
│   │   └── local-plugin.md
│   │       prereqs: [generators/registration]
│   ├──[contains]─→ generators/INDEX.md
│   │   prereqs: [plugins/local-plugin]
│   ├──[contains]─→ boundaries/INDEX.md
│   │   cross: [effect-v4/INDEX]
│   └──[contains]─→ effect-v4/INDEX.md
│       cross: [boundaries/INDEX]

Agent reads GRAPH.md first to plan traversal. Edges are typed: routes, contains, prereqs, cross.

4. Plugin Briefs — Standardized

Each plugin gets its own file under plugins/ following the Plugin Brief template:

Current (plugins/INDEX.md)

### 1. @nx/vite/plugin
**Infers from**: vite.config.* / vitest.config.*
**Targets**: build, test, serve, dev...

Flat list. No options. No "when to care." No cross-refs.

Proposed (plugins/vite.md)

# @nx/vite/plugin

> up: INDEX.md
> prereqs: none
> provides: build, test, dev targets

## Infers From
vite.config.* / vitest.config.*

## Targets
| Target | Executor | Cache |
|---|---|---|
| build | vite build | ✓ |
| test | vitest run | ✓ |

## Options (nx.json)
buildTargetName, testTargetName...

## When To Care
Creating a Vite-based library or app.
