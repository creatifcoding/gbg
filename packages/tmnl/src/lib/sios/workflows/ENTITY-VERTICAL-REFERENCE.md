# Entity-Based Software Development — Reference Guide

A complete instruction set for building domain software using the Effect-TS entity vertical pattern. Written for agent consumption — assumes no prior context. Designed to bootstrap a builder agent from zero to productive in one read.

---

## Core Concept

Every domain entity follows an **8-layer vertical stack**. Each layer has a single responsibility, a fixed file location, and a typed contract with the layers above and below it.

```
                     Consumer (React, CLI, test)
                           │
                    ┌──────▼──────┐
           Layer 8: │    HTTP     │  REST API via EntityProxy
                    └──────┬──────┘
                    ┌──────▼──────┐
           Layer 7: │    Repo     │  Direct SQL for read-heavy queries
                    └──────┬──────┘
                    ┌──────▼──────┐
           Layer 6: │   Model     │  SQL column mapping + DDL
                    └──────┬──────┘
                    ┌──────▼──────┐
           Layer 5: │   Entity    │  Public Rpc contract + cluster routing
                    └──────┬──────┘
                    ┌──────▼──────┐
           Layer 4: │  Machine    │  State machine orchestration
                    └──────┬──────┘
                    ┌──────▼──────┐
           Layer 3: │   State     │  Persistence interface (in-memory / SQL)
                    └──────┬──────┘
                    ┌──────▼──────┐
           Layer 2: │   Graph     │  State transition validation
                    └──────┬──────┘
                    ┌──────▼──────┐
           Layer 1: │  Schema     │  Domain types + methods + params
                    └─────────────┘
```

Two kinds of entities exist:
- **Lifecycle entities** — Have meaningful state transitions. Use all 8 layers. (Example: Project with bidding→active→complete)
- **CRUD entities** — Just data. Use layers 1, 3, 5, 6, 7, 8. Skip Graph (2) and Machine (4). (Example: TimeEntry — append-only records)

## Layer 1: Schema

**File:** `schemas/{entity}/schema.ts`
**Dependencies:** None
**Exports:** Entity class, CreateParams, UpdateParams, status enum

### What It Is

The schema is the **single source of truth** for an entity's shape. It defines:
- Every field the entity has
- The entity's status/lifecycle enum
- Domain methods that interpret the entity's data
- Create params (what you need to make one)
- Update params (what you can change after creation)

### Pattern

```typescript
import { Schema } from 'effect'

// Status enum — the lifecycle states
export const ProjectStatus = Schema.Literal(
  'bidding', 'awarded', 'mobilising', 'active',
  'commissioning', 'complete', 'on_hold', 'cancelled'
)
export type ProjectStatus = typeof ProjectStatus.Type

// The entity — Schema.TaggedClass with METHODS
export class Project extends Schema.TaggedClass<Project>()('Project', {
  id: ProjectId,
  name: Schema.NonEmptyString,
  status: ProjectStatus,
  budgetedCost: Schema.Number,
  // ... all fields
}) {
  // Domain methods — the entity interprets itself
  isActive(): boolean {
    return this.status === 'active' || this.status === 'commissioning'
  }
  isBrownfield(): boolean {
    return this.siteCondition.startsWith('brownfield')
  }
}

// Create params — what you need to make one (NOT the full entity shape)
export const CreateProjectParams = Schema.Struct({
  name: Schema.NonEmptyString,
  code: Schema.NonEmptyString,
  budgetedCost: Schema.Number.pipe(Schema.greaterThanOrEqualTo(0)),
  // ... only the fields the caller provides
})

// Update params — what you can change (all optional)
export const UpdateProjectParams = Schema.Struct({
  name: Schema.optional(Schema.NonEmptyString),
  budgetedCost: Schema.optional(Schema.Number),
  // ...
})
```

### Critical Rules

1. **TaggedClass, not TaggedStruct.** Entities have methods. They're calculators, not data bags.
2. **Status is a Schema.Literal enum, not a raw string union.** Gives runtime validation.
3. **CreateParams ≠ Entity shape.** CreateParams has only what the caller provides. ID, timestamps, and defaults are generated by the state service.
4. **Methods must be pure.** No side effects. They read `this` fields and return derived values.
5. **One entity per file.** Entity + CreateParams + UpdateParams + status enum all in the same file.

## Layer 2: Graph

**File:** `machines/graphs/{entity}-graph.ts`
**Dependencies:** None (pure data structure)
**Exports:** Graph instance, typed state/action enums, per-action validators

### What It Is

A directed graph defining every valid state transition. Used by the Machine (Layer 4) to validate transitions before executing them. Built once at module load, O(1) lookup thereafter.

### Pattern

```typescript
import { Graph, Option } from 'effect'

export type ProjectStateNode = 'bidding' | 'awarded' | 'mobilising' | /* ... */
export type ProjectTransitionAction = 'award' | 'mobilise' | 'activate' | /* ... */

const nodeIndices: Record<string, number> = {}

export const projectGraph = Graph.directed<ProjectStateNode, ProjectTransitionAction>(
  (mutable) => {
    // Add nodes — returns index
    nodeIndices.bidding = Graph.addNode(mutable, 'bidding')
    nodeIndices.awarded = Graph.addNode(mutable, 'awarded')
    // ...

    // Add edges — from index, to index, action label
    Graph.addEdge(mutable, nodeIndices.bidding, nodeIndices.awarded, 'award')
    Graph.addEdge(mutable, nodeIndices.awarded, nodeIndices.mobilising, 'mobilise')
    // ...
  }
)

// Per-action validators (O(1) — just a lookup)
export const canAward = (s: ProjectStateNode) => s === 'bidding'
export const canMobilise = (s: ProjectStateNode) => s === 'awarded'
export const isTerminalState = (s: ProjectStateNode) =>
  s === 'complete' || s === 'cancelled'
```

### Critical Rules

1. **`Graph.addNode(mutable, value)` — NOT `mutable.node(value)`.** The API uses free functions, not methods.
2. **`Graph.addEdge(mutable, fromIndex, toIndex, label)`** — Uses node indices from addNode return values.
3. **Store indices in a module-level record** for readable edge definitions.
4. **CRUD entities skip this layer entirely.**

## Layer 3: State

**File:** `state/{Entity}State.ts`
**Dependencies:** Schema (Layer 1)
**Exports:** Context.Tag, interface, in-memory implementation, not-found error

### What It Is

The persistence interface. Defines create/get/set/list/delete operations. Ships with an in-memory implementation (`Ref<Map>`) for testing and demos. Production swaps to SQL implementation via Layer.

### Pattern

```typescript
import { Context, Layer, Effect, Ref, Option, HashMap } from 'effect'

// Error type
export class ProjectNotFoundError extends Schema.TaggedError<...>()('ProjectNotFoundError', {
  projectId: Schema.String
}) {}

// Interface
export interface ProjectStateShape {
  readonly create: (params: CreateProjectParams) => Effect.Effect<Project, ...>
  readonly get: (id: ProjectId) => Effect.Effect<Project, ProjectNotFoundError>
  readonly set: (project: Project) => Effect.Effect<void>
  readonly list: (filter?: ProjectFilter) => Effect.Effect<readonly Project[]>
  readonly delete: (id: ProjectId) => Effect.Effect<void>
}

// Tag
export class ProjectState extends Context.Tag('sios/ProjectState')<
  ProjectState, ProjectStateShape
>() {}

// In-memory implementation
export const ProjectStateInMemory = Layer.effect(
  ProjectState,
  Effect.gen(function* () {
    const store = yield* Ref.make(HashMap.empty<ProjectId, Project>())

    const create = (params: CreateProjectParams) =>
      Effect.gen(function* () {
        const id = generateProjectId()
        const project = new Project({
          id,
          ...params,
          status: 'bidding',  // default initial state
          createdAt: DateTime.unsafeNow(),
          // ... defaults
        })
        yield* Ref.update(store, HashMap.set(id, project))
        return project
      })

    // ... get, set, list, delete

    return { create, get, set, list, delete: del } satisfies ProjectStateShape
  })
)
```

### Critical Rules

1. **`Context.Tag` for the service, `Layer.effect` for the implementation.**
2. **In-memory uses `Ref<HashMap>`.** Not a plain Map — Effect's Ref is fiber-safe.
3. **`create()` generates the ID and sets defaults.** The caller provides CreateParams, the state service adds id, timestamps, initial status.
4. **`satisfies` the interface.** TypeScript checks the implementation matches the contract.
5. **Every entity gets one**, including CRUD entities.

## Layer 4: Machine

**File:** `machines/{Entity}Machine.ts`
**Dependencies:** Schema (1), Graph (2), State (3)
**Exports:** Machine factory function, Internal* request classes

### What It Is

The state machine orchestrator. Uses `Machine.make()` from `@effect/experimental`. Defines one procedure per operation. Each procedure: validate the graph transition → mutate state → return result.

### Pattern

```typescript
import { Machine } from '@effect/experimental'
import { Schema, Effect } from 'effect'

// Internal request (machine's private vocabulary)
export class InternalCreateProject extends Schema.TaggedRequest<InternalCreateProject>()(
  'InternalCreateProject',
  { failure: MachineProjectCreateError, success: Project, payload: { params: CreateProjectParams } }
) {}

export class InternalAwardProject extends Schema.TaggedRequest<InternalAwardProject>()(
  'InternalAwardProject',
  { failure: Schema.Union(MachineNotFound, MachineInvalidTransition), success: Project, payload: { projectId: Schema.String } }
) {}

// Machine factory
export const makeProjectMachine = (deps: { state: ProjectStateShape, flags: FeatureFlags }) =>
  Machine.make({
    state: undefined,  // machine-level state (unused here — entity state is in the state service)
  }).pipe(
    Machine.procedures.add<InternalCreateProject>()(
      'InternalCreateProject',
      ({ request }) => Effect.gen(function* () {
        const project = yield* deps.state.create(request.params)
        return [project, undefined]  // [result, newMachineState]
      })
    ),
    Machine.procedures.add<InternalAwardProject>()(
      'InternalAwardProject',
      ({ request }) => Effect.gen(function* () {
        const project = yield* deps.state.get(request.projectId)
        // Validate graph transition
        if (!canAward(project.status)) {
          return yield* Effect.fail(new MachineInvalidTransition({ ... }))
        }
        const updated = new Project({ ...project, status: 'awarded' })
        yield* deps.state.set(updated)
        return [updated, undefined]
      })
    ),
    // ... more procedures
  )
```

### Critical Rules

1. **`Internal*` classes use `Schema.TaggedRequest`, not `Rpc.make`.** These are machine-private.
2. **Machine factory takes deps as argument**, not from context. Deps: `{ state, flags }`.
3. **Every transition procedure validates the graph** before mutating state.
4. **Return tuple `[result, newMachineState]`** from every procedure. Machine state is usually `undefined` for entity machines (state lives in the state service).
5. **CRUD entities skip this layer.**

## Layer 5: Entity

**File:** `entity/{Entity}Entity.ts`
**Dependencies:** Schema (1), Machine (4), State (3)
**Exports:** Entity instance, Rpc classes, handler layer

### What It Is

The public API contract. Defines Rpc operations that external consumers (HTTP, cluster, RPC clients) use. The Entity handler boots the machine and maps each Rpc to an Internal* send.

### Pattern

```typescript
import { Entity } from '@effect/cluster'
import { Rpc } from '@effect/rpc'

// Public Rpc (external contract)
export class CreateProjectRpc extends Rpc.make('Project.Create', {
  payload: CreateProjectParams,
  primaryKey: ({ code }) => code,
  success: Project,
  error: RpcProjectCreateError,
}) {}

// Entity definition
export const ProjectEntity = Entity.make('Project', [
  CreateProjectRpc, GetProjectRpc, AwardProjectRpc, /* ... */
])

// Handler — boots machine, maps Rpc → Internal*
export const ProjectEntityHandlers = ProjectEntity.toLayer(
  Effect.gen(function* () {
    const state = yield* ProjectState
    const flags = yield* SiosFeatureFlags
    const machine = makeProjectMachine({ state, flags })
    const actor = yield* Machine.boot(machine)

    return ProjectEntity.of({
      'Project.Create': (env) =>
        actor.send(new InternalCreateProject({ params: env.payload })).pipe(
          Effect.catchTag('MachineProjectCreateError', (e) =>
            Effect.fail(new RpcProjectCreateError({ message: e.message }))
          )
        ),
      // ... map each Rpc to actor.send(Internal*)
    })
  })
)
```

### Critical Rules

1. **Rpc.make for the public contract, Internal* for the machine.** Never expose Internal* outside the entity module.
2. **Error mapping in the handler.** Machine errors → Rpc errors. The public API has its own error types.
3. **`Entity.of({...})` must match every Rpc** registered in `Entity.make`.
4. **CRUD entities** still have Entity.make + Rpc.make, but the handler calls state service directly instead of booting a machine.

## Layer 6: Model

**File:** `models/{Entity}Model.ts`
**Dependencies:** Schema (1) — for identifiers and common types
**Exports:** Model class, DDL creation Effect

### What It Is

The SQL mapping. `Model.Class` maps entity fields to database columns. Co-located DDL creates the table with constraints and indexes.

### Pattern

```typescript
import { Model } from '@effect/sql'
import { SqlClient } from '@effect/sql'

export class ProjectModel extends Model.Class<ProjectModel>('ProjectModel')({
  id: Model.GeneratedByApp(ProjectId),    // App generates ID, not DB
  name: Schema.NonEmptyString,
  status: Schema.String,
  budgetedCost: NumericFromPg,             // NUMERIC → number transform
  description: Model.FieldOption(Schema.String),  // nullable → Option
  metadata: OptionalMetadata,              // JSONB → Record
  createdAt: CreatedAt,                    // TIMESTAMPTZ → DateTime
  updatedAt: UpdatedAtNullable,
}) {}

export const createProjectsTable = Effect.gen(function* () {
  const sql = yield* SqlClient.SqlClient
  yield* sql`
    CREATE TABLE IF NOT EXISTS sios.projects (
      id            TEXT PRIMARY KEY,
      name          TEXT NOT NULL,
      status        TEXT NOT NULL CHECK (status IN ('bidding','awarded',...)),
      budgeted_cost NUMERIC NOT NULL DEFAULT 0,
      description   TEXT,
      metadata      JSONB DEFAULT '{}',
      created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
      updated_at    TIMESTAMPTZ
    )
  `
  yield* sql`CREATE INDEX IF NOT EXISTS idx_proj_status ON sios.projects(status)`
})
```

### Critical Rules

1. **`Model.GeneratedByApp`** for IDs — the app generates them, not the database.
2. **`Model.FieldOption`** for nullable columns — maps `null` ↔ `Option`.
3. **CHECK constraints in DDL** for enum columns — matches the Schema.Literal values.
4. **Co-locate Model + DDL** in the same file. They describe the same table.
5. **Snake_case in DDL, camelCase in Model.** The repo's `selectColumns` handles the aliasing.

## Layer 7: Repo

**File:** `repos/{Entity}Repo.ts`
**Dependencies:** Model (6)
**Exports:** Context.Tag, Live layer

### What It Is

Direct SQL queries for read-heavy operations. Column alias helpers, decode utilities for `null → Option` mapping.

### Pattern

```typescript
export const ProjectRepoLive = Layer.effect(
  ProjectRepo,
  Effect.gen(function* () {
    const sql = yield* SqlClient.SqlClient

    const selectColumns = sql`
      id,
      name,
      status,
      budgeted_cost AS "budgetedCost",
      description,
      metadata,
      created_at AS "createdAt",
      updated_at AS "updatedAt"
    `

    const findById = (id: ProjectId) =>
      Effect.gen(function* () {
        const rows = yield* sql`
          SELECT ${selectColumns}
          FROM sios.projects WHERE id = ${id} LIMIT 1
        `
        return yield* decodeOptional(ProjectModel)(rows)
      })

    // ... findAll, findByStatus, insert, update, delete

    return { findById, /* ... */ } satisfies ProjectRepository
  })
)
```

### Critical Rules

1. **`selectColumns` aliases snake_case → camelCase** for every column. This is the only place the mapping happens.
2. **`decodeOptional`, `decodeRows`, `decodeFirst`** from shared `_decode.ts`. Never hand-parse SQL results.
3. **`prepareUpdate`** for update operations — converts `Option → null` and `camelCase → snake_case`.
4. **JSONB fields need `JSON.stringify`** in INSERT and `{ jsonbFields: [...] }` in prepareUpdate.
5. **Domain-specific queries** belong here (e.g., `sumActualsByProject`, `findOverdueSLA`, `findDeployable`).

## Layer 8: HTTP

**File:** `http/api.ts` + `http/proxy-handlers.ts` + `http/server.ts`
**Dependencies:** Entity (5)
**Exports:** HttpApi, server composition layer

### What It Is

REST API auto-generated from Entity Rpc definitions. Each entity gets a group of POST endpoints.

### Pattern

```typescript
// api.ts
export class SiosApi extends HttpApi.make('sios-api')
  .annotateContext(OpenApi.annotations({ title: 'SIOS', version: '1.0.0' }))
  .add(EntityProxy.toHttpApiGroup('projects', ProjectEntity).prefix('/api/sios/projects'))
  .add(EntityProxy.toHttpApiGroup('zones', ZoneEntity).prefix('/api/sios/zones'))
  // ...
{}

// proxy-handlers.ts
export const ProxyHandlers = Layer.mergeAll(
  EntityProxyServer.layerHttpApi(SiosApi, 'projects', ProjectEntity),
  EntityProxyServer.layerHttpApi(SiosApi, 'zones', ZoneEntity),
  // ...
)

// server.ts
export const SiosHttpServerDev = HttpApiBuilder.serve(HttpMiddleware.cors()).pipe(
  Layer.provide(HttpApiSwagger.layer({ path: '/docs' })),
  Layer.provide(ApiLive),
  Layer.provide(AllEntityHandlers),
  Layer.provide(AllStateServicesInMemory),
  Layer.provide(ClusterDev),
  Layer.provide(BunHttpServer.layer({ port: 3000 })),
)
```

### Critical Rules

1. **Import entities directly from their files**, not from barrel. Avoids name collisions.
2. **Group names in api.ts MUST match proxy-handlers.ts.**
3. **Server composition is a Layer chain** — order matters (provide dependencies after consumers).

## Cross-Cutting Layers

### EntityStack

Merges all entity handler layers into one:

```typescript
export const AllEntityHandlers = Layer.mergeAll(
  ProjectEntityHandlers, ZoneEntityHandlers, /* ... all 9 */
)

export const FullTestingStack = AllEntityHandlers.pipe(
  Layer.provide(AllStateServicesInMemory),
  Layer.provide(SiosFlagsDisabledLayer),
)
```

### Migrations

Orders DDL creation by FK dependency:

```typescript
export const siosMigrations = {
  '0000_schema': createSchema,
  '0001_projects': createProjectsTable,   // no FK deps
  '0002_zones': createZonesTable,          // FK → projects
  '0003_work_packages': createWPTable,     // FK → projects, zones
  // ... dependency order
}
export const migrationLoader = Migrator.fromRecord(siosMigrations)
```

### Feature Flags

```typescript
export class SiosFeatureFlags extends Context.Tag('sios/FeatureFlags')<...>() {}
export const SiosFlagsDisabledLayer = Layer.succeed(SiosFeatureFlags, { /* all false */ })
export const SiosFlagsEnabledLayer = Layer.succeed(SiosFeatureFlags, { /* configurable */ })
```

## Build Order Checklist

For a new domain with N entities:

```
□ Phase 1 — Foundation
  □ schemas/identifiers.ts (branded IDs for all entities)
  □ schemas/common/types.ts (shared base fields)
  □ infrastructure/feature-flags.ts
  □ For each entity (dependency order):
    □ schemas/{entity}/schema.ts (TaggedClass + params)
    □ machines/graphs/{entity}-graph.ts (lifecycle entities only)
    □ state/{Entity}State.ts (Context.Tag + in-memory impl)
  □ state/index.ts (AllStateServicesInMemory)
  □ tsc --noEmit → 0 errors

□ Phase 2 — Machines + Persistence
  □ For each lifecycle entity:
    □ machines/{Entity}Machine.ts (Machine.make + Internal*)
  □ For each entity:
    □ entity/{Entity}Entity.ts (Rpc.make + handler)
  □ entity/EntityStack.ts (Layer.mergeAll + testing stacks)
  □ models/_common.ts (shared transforms)
  □ For each entity:
    □ models/{Entity}Model.ts (Model.Class + DDL)
  □ models/_migrations.ts (Migrator.fromRecord)
  □ tsc --noEmit → 0 errors

□ Phase 3 — API + Test
  □ repos/_decode.ts (shared decode utilities)
  □ For each entity:
    □ repos/{Entity}Repo.ts (SQL queries)
  □ repos/index.ts (AllReposLive)
  □ http/api.ts, proxy-handlers.ts, cluster.ts, server.ts
  □ __tests__/e2e-lifecycle.test.ts
  □ tsc --noEmit → 0 errors
  □ vitest run → all tests pass
```
