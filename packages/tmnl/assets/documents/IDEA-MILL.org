- Velocity: Semantic classes = fewer decisions, faster builds
- Maintainability: Change token once, propagate everywhere

*** REFINED CONCEPT
Option A: Shift everything up
- tmnl-xs = 12px, tmnl-sm = 14px, tmnl-base = 16px

Option C: Semantic-only fix
- Don't touch raw sizes
- Fix .tmnl-type-* to use larger underlying sizes
- Components use semantic only, never raw

*** WHY IT MATTERS
Prime is squinting. That's a UX failure.

*** RESEARCH REPORT: Multi-Source Completion Architectures

**** Emacs: Consult/Vertico Pattern
:PROPERTIES:
:SOURCE_URL: https://github.com/minad/consult
:VERTICO_URL: https://github.com/minad/vertico
:END:

***** Ontological Primitives

| Concept       | Description                                           | TMNL Analog         |
|---------------+-------------------------------------------------------+---------------------|
| Source        | Candidate generator with metadata                     | SearchDriver        |
| Category      | Completion category for styling/actions               | ResultType          |
| Narrowing     | Filter to single source via key prefix                | Namespace filtering |
| Async Pipeline| Composable transform chain for candidates             | Effect.Stream       |
| Multi-source  | =consult--multi= aggregates sources into unified list | Indices builder     |

***** Source Shape (Consult)
#+BEGIN_SRC elisp
(defvar consult-source-bookmark
  `(:name     "Bookmark"        ; Display name for group
    :narrow   ?m               ; Narrowing key (press "m SPC" to filter)
    :category bookmark         ; Completion category
    :face     consult-bookmark ; Face for candidates
    :history  bookmark-history ; History variable
    :items    ,#'bookmark-all-names ; Candidate generator (sync)
    :async    nil              ; Alternative: async generator
    :action   ,#'consult--bookmark-action ; Action on select
    :state    nil              ; Preview state function
    :hidden   nil              ; Hidden by default?
    :enabled  ,#'always))      ; Enable predicate
#+END_SRC

***** Key Design Decisions

1. *Separation of Concerns*
   - Source: ONLY provides candidates + metadata
   - UI (Vertico): Renders candidates, handles selection
   - Actions (Embark): Context-sensitive operations on candidates
   - No source owns filtering — completion-style handles it

2. *Narrowing Protocol*
   - =consult-narrow-key= + source key = filter to single source
   - Widening key returns to all sources
   - Implemented via =minibuffer-completion-predicate=

3. *Async Pipeline Composition*
   #+BEGIN_SRC elisp
   (consult--async-pipeline
    (consult--async-split)        ; Split input for async/filter parts
    (consult--async-throttle)     ; Debounce input
    (consult--async-process ...)  ; External process (grep/find)
    (consult--async-transform ..) ; Transform candidates
    (consult--async-highlight ..) ; Highlight matches
    (consult--async-indicator))   ; Show progress indicator
   #+END_SRC

4. *consult--multi Source Aggregation*
   - Each source defines =:items= (sync) or =:async= (stream)
   - Sources can have =:hidden= flag (excluded by default)
   - =:narrow= key activates single-source mode
   - Categories enable per-type annotations (Marginalia)

***** Vertico Rendering Model
- Minimal vertical completion UI
- Uses built-in =completing-read= infrastructure
- Candidate recomputation on every keystroke
- Lazy highlighting via =completion-lazy-hilit=
- Groups rendered with =vertico-group-format=

**** Zed: Picker Delegate Pattern
:PROPERTIES:
:SOURCE_URL: https://github.com/zed-industries/zed/tree/main/crates/command_palette
:END:

***** Ontological Primitives

| Concept      | Description                            | TMNL Analog      |
|--------------+----------------------------------------+------------------|
| Picker       | UI shell for selection                 | CommandBar       |
| Delegate     | Handles candidates + selection         | Search driver    |
| Match        | fuzzy::match_strings scoring           | FlexSearch score |
| Intercept    | Dynamic candidate injection            | Source priority  |

***** Key Design Decisions

1. *Single Command List*
   - All commands flatten to =CommandInterceptResult::actions=
   - No persistent multi-source aggregation
   - Dynamic injection via =CommandInterceptResult=

2. *Background Matching*
   #+BEGIN_SRC rust
   cx.spawn(async move |this, mut cx| {
       let matches = fuzzy::match_strings(...);
       this.update(&mut cx, |this, cx| {
           this.delegate.matches = matches;
           cx.notify();
       })
   })
   #+END_SRC

3. *No Narrowing*
   - All commands always visible
   - Filtering is pure fuzzy match, no categorical separation

**** VSCode: Command Palette Architecture
:PROPERTIES:
:DOCUMENTATION: https://code.visualstudio.com/docs/getstarted/userinterface#_command-palette
:END:

***** Key Design Decisions

1. *Prefix-Based Mode Switching*
   | Prefix | Mode                  |
   |--------+-----------------------|
   | (none) | Commands              |
   | >      | Commands (explicit)   |
   | @      | Go to symbol          |
   | #      | Global symbol search  |
   | :      | Go to line            |

2. *Extensions Register Commands*
   - Commands registered with =vscode.commands.registerCommand=
   - Palette pulls from global registry
   - No multi-source composition — single command namespace

*** REFINED CONCEPT: TMNL Indices Builder

**** Architecture: Effect.Stream Composition

Based on research, the Consult =consult--async-pipeline= pattern maps
directly to Effect.Stream composition:

#+BEGIN_SRC typescript
// Source definition (like consult-source-*)
interface SearchSource<T> {
  readonly id: string
  readonly name: string
  readonly narrowKey?: string      // 't' for testbeds, 'c' for commands
  readonly category: string        // For styling/actions
  readonly hidden?: boolean        // Excluded by default?
  readonly enabled?: () => boolean // Predicate
  readonly items: () => Effect.Effect<readonly T[]> | Stream.Stream<T>
  readonly action: (item: T) => Effect.Effect<void>
  readonly preview?: (item: T) => Effect.Effect<PreviewData>
}

// Indices builder (like consult--multi)
const createIndicesBuilder = <T extends SearchItem>(
  sources: readonly SearchSource<T>[]
) => Effect.gen(function*() {
  // Parallel source aggregation
  const streams = sources
    .filter(s => !s.hidden && (s.enabled?.() ?? true))
    .map(source => pipe(
      typeof source.items === 'function' && Stream.isStream(source.items())
        ? source.items()
        : Stream.fromIterable(yield* source.items()),
      Stream.map(item => ({ ...item, _source: source.id })),
      Stream.catchAll(() => Stream.empty) // Source failure isolation
    ))

  // Merge all sources (unordered for speed)
  return Stream.mergeAll(streams, { concurrency: 'unbounded' })
})

// Narrowing filter (like consult-narrow)
const narrowToSource = <T extends SearchItem>(
  stream: Stream.Stream<T>,
  narrowKey: string | null
) => narrowKey
  ? Stream.filter(stream, item => item._source === sourceByKey.get(narrowKey))
  : stream
#+END_SRC

**** Key Design Decisions for TMNL

1. *Source Isolation via Effect.catchAll*
   - One failing source doesn't crash the whole search
   - Logged for debugging but UX uninterrupted

2. *Narrowing via Stream.filter*
   - Press narrow key (e.g., 't') + space to filter to testbeds only
   - Widening resets filter to =null=

3. *Progressive Updates via Stream.merge*
   - Fast sources appear immediately
   - Slow sources (e.g., file search) update asynchronously

4. *No Ownership Hierarchy*
   - Sources are DATA definitions only
   - =src/lib/search= owns FlexSearch/Linear drivers
   - =src/lib/indices= owns source registration + composition
   - CommandBar consumes indices, doesn't own them

**** Tauri Integration Note (Files)

File search will be implemented on the Rust side via Tauri, NOT in TypeScript.

Rationale:
- Performance: Rust file traversal >> JS
- Native access: No browser sandbox limitations
- Existing patterns: ripgrep, fd, ignore crate

When implementing, research:
- =ignore= crate for .gitignore-aware traversal
- =walkdir= for recursive directory walking
- Tauri command pattern for async results
- Event-based streaming for progressive updates

The TypeScript side will consume via:
#+BEGIN_SRC typescript
// Tauri command (one-shot)
const results = await invoke<FileSearchResult[]>('search_files', { query })

// Or Tauri events (streaming)
await listen<FileSearchResult>('file_search_result', (event) => {
  // Progressive update
})
#+END_SRC

*** WHY IT MATTERS
- *Composability*: Sources are independent, combine freely
- *Isolation*: Source failures don't cascade
- *Performance*: Progressive updates, lazy loading
- *Extensibility*: Add new sources without touching CommandBar
- *Ownership clarity*: No component "owns" search
